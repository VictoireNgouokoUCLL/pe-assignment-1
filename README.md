# Assignment 1 — Take over a server (modules 1–5)

> 💻 **Windows: run every command in Git Bash** (installed with Git) — not PowerShell or cmd.
> Make sure your editor saves shell scripts and config files with **LF** line endings.

**This assignment counts towards your marks: 3 of the 20 points.**
It covers modules 1–5. The weekly labs are your preparation for it.

**Deadline: Sunday 8 November 2026, 23:59** — you hand in a zip on Toledo
before that moment. See "Hand in on Toledo" at the end of `assignment.md`.

---

## Start here

```bash
./bin/personalise.sh      # writes spec.md and .env — run this first
cat spec.md               # your personal parameters
docker compose up -d      # starts the server you are taking over
docker compose exec server bash
```

Every student gets different values: a different hostname, different accounts
and UIDs, a different SSH port, a different backup schedule. Your neighbour's
answer does not fit your server.

The server you inherit is not clean. **Exactly one thing about it is wrong.**
Finding it, explaining it and repairing it is part of the assignment.

Then read [assignment.md](assignment.md) for what you have to deliver.

## What you hand in

Everything lives in this repository. Nothing is submitted anywhere else.

| Path | What goes in it |
|---|---|
| `spec.md`, `.env` | generated — commit them, do not edit them |
| `submission/` (config files) | `sudoers.d/`, `default-locale`, `sshd_hardening.conf`, `packages.txt`, `timezone`, `chrony.conf`, `backup.sh`, `crontab-service.txt` |
| `submission/report.txt` | generated by `./bin/collect-evidence.sh <your private key>` against your running server, including SSH login tests |
| `submission/defect-raw.txt` | the raw output that put you on the trail of the fault |
| `submission/defect.md` | what was wrong, how you found it, how you fixed it |
| `submission/justification.md` | three choices justified, plus your AI statement |

Inside the container your repository is `/lab`, so you copy files to
`/lab/submission/`.

On your laptop, in the repository folder:

```bash
./check.sh     # optional: only checks that files exist and are not empty
git add submission/ spec.md .env && git commit -m "assignment 1: <what you did>" && git push
```

`check.sh` does not mark your work and a green result is not a grade.

## Rules

- **AI tools are allowed.** You declare what you used in
  `submission/justification.md`: what you asked, what came back, what you
  changed and why. A submission without that section is incomplete.
- **Work individually.** Discussing approaches is fine; handing over files is
  not. Your parameters are unique, so a shared answer will not fit anyway.
- **Never commit a private key.** `.gitignore` guards the usual names, but it
  is your responsibility.
- Your repository is private. Keep it that way.

The practical exam in January tests the same skills on a fresh server, with
different parameters and limited time. It is open book: you may use your own
notes and files, this repository included. They only help if you understand
what is in them. What you build here is the rehearsal.
